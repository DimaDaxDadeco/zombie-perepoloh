# Оружие

Всё оружие стреляет автоматически — это основа управления игрой (см.
[game-design.md](game-design.md)). Целиться не нужно, цель выбирается сама.

## Базовый класс — `weapons/weapon.js`

```js
class Weapon {
  stars          // 1..5, текущий уровень
  stat(key)      // значение характеристики для текущего числа звёзд
  update(dt, world)
  fire(world, target)
}
```

Характеристики хранятся в `CONFIG.weapons[id]` массивами по звёздам: индекс 0 —
одна звезда, индекс 4 — пять. `stat('damage')` сам берёт нужный элемент и
корректно работает, если массив короче пяти (берётся последний).

**Владелец приходит параметром**: `update(dt, world, owner)` и
`fire(world, target, owner)`. Раньше здесь стоял `world.player` — пока герой
был один, это совпадало. Брать владельца из мира нельзя: при игре вдвоём
оружие второго целилось бы от первого. Добавляя оружие, используйте `owner`,
а не `world.player`.

Стандартный `update()` тикает перезарядку, ищет ближайшего врага и вызывает
`fire()`. Оружию без перезарядки (вертушка) достаточно переопределить `update()`
целиком.

**`dt` приходит уже масштабированным.** `Player.update()` умножает его на
`fireRateFactor`, и во время «Турбо» Робота время для оружия идёт вдвое
быстрее. Благодаря этому способность работает со всеми восемью стволами разом —
и с вертушкой, у которой свой `update()`, — а сами классы про неё не знают.
Условие одно: считайте время только по своему `dt`, не заглядывая в
`performance.now()`.

**Цель всегда видима.** `world.findNearestEnemy()` по умолчанию отбрасывает
врагов за краем экрана: зомби заходят из-за границы арены, и стрельба по
невидимой цели выглядит как «оружие палит в пустоту». Фильтр живёт в одном
месте — `Round.isOnScreen()` — и действует сразу на все восемь стволов. Если
нужен обратный эффект, передайте `{ onScreenOnly: false }`.

## Восемь реализаций — `weapons/weapons.js`

| Оружие | Класс | Как работает |
|---|---|---|
| 💧 Водяной пистолет | `WaterGun` | Капли летят веером в ближайшего зомби. |
| 🍅 Помидорометалка | `TomatoLauncher` | Навесом в точку, где стоит цель, взрыв по площади. |
| ⚡ Молния | `Lightning` | Мгновенный урон с перескоком на соседей в радиусе `chainRadius`. |
| 🌀 Вертушка | `Spinner` | Лопасти вращаются вокруг героя, бьют по касанию. |
| 🥕 Ракета-морковка | `CarrotRocket` | Самонаводящаяся ракета, взрыв по площади. |
| 🔥 Огнемёт | `Flamethrower` | Струя язычков пламени, поджигает задетых. Бьёт ближе прочих: пламя гаснет на дистанции `range`. |
| ❄️ Ледяная пушка | `IceCannon` | Снежинки бьют и замораживают — зомби ползёт медленнее. |
| ⚔️ Световой меч | `LightSaber` | Взмах дугой перед героем, бьёт всех в секторе. Снарядов не создаёт. |
| 👁 Лазерные глаза | `LaserEyes` | Непрерывный луч, прожигает всех на линии до `maxTargets`. Снарядов не создаёт. |
| 🪃 Бумеранг | `BoomerangThrower` | Улетает, разворачивается и возвращается, задевая всех дважды. |
| 🐝 Рой пчёл | `BeeSwarm` | Несколько мелких самонаводящихся, живут пару секунд. |

Две детали, о которых легко забыть:

- **Молния** ведёт `Set` уже задетых зомби, иначе разряд прыгал бы между двумя
  соседями туда-обратно.
- **Вертушка** держит `Map` перезарядок по зомби (`hitCooldown`), иначе она
  наносила бы урон каждый кадр и убивала бы всё мгновенно.

`draw()` есть у всех: базовый класс рисует ствол в руке, а вертушка
переопределяет его своими лопастями. `Player.draw()` проходит по всему оружию и
вызывает `weapon.draw?.(ctx, this)` — см. раздел «Оружие в руке» ниже.

## Как добавить новое оружие

1. **Опишите характеристики** в `CONFIG.weapons` (`js/config.js`):

   ```js
   bubble: {
     name: 'Пузыри', emoji: '🫧',
     cooldown: [1.2, 1.0, 0.9, 0.8, 0.7],
     damage:   [2, 2, 3, 3, 4],
     speed: 260,
   },
   ```

2. **Напишите класс** в `weapons/weapons.js`:

   ```js
   class BubbleGun extends Weapon {
     constructor() { super('bubble'); }
     fire(world, target) {
       const p = world.player;
       const angle = Math.atan2(target.y - p.y, target.x - p.x);
       world.addProjectile(new Bullet(p.x, p.y, angle, this.spec.speed, this.stat('damage')));
     }
   }
   ```

3. **Зарегистрируйте** его в `WEAPON_CLASSES` в том же файле.

Всё. Оружие само появится в карточках прокачки: `systems/levelup.js` берёт
список из `ALL_WEAPON_IDS`, который строится по ключам конфига.

**Бумеранг** держит ссылку на владельца, а не на `world.player`: вдвоём
бумеранг второго обязан вернуться ко второму. Задевает дважды за счёт того,
что `Set` задетых очищается на развороте. `isOffscreen` ему намеренно **не**
применяется — она убила бы бумеранг, летящий назад из-за края; от вечного
полёта страхует таймаут.

**Пчёлы** — тот случай, когда правило «сначала числами» проверено и не
сработало: `Rocket` на любой смерти зовёт `explode()` со звуком взрыва и
кольцом, а пчела должна тихо истаять. Зато самонаведение вынесено из ракеты в
общую `steerToward()` и переиспользовано.

Если нужен снаряд с новым поведением — добавьте класс в
`entities/projectile.js` рядом с `Bullet`, `Lob` и `Rocket`.

## Стихийные статусы

Огнемёт и ледяная пушка вешают на зомби статус — это единственная механика,
где урон приходит не в момент попадания. Живёт она в `Zombie`
([zombie.js](../js/entities/zombie.js)):

| Статус | Метод | Что делает |
|---|---|---|
| Горение | `ignite(dps, duration)` | урон капает раз в секунду ещё N секунд |
| Заморозка | `freeze(factor, duration)` | скорость умножается на factor |

Оба **не складываются, а продлеваются**: повторное попадание берёт больший
эффект и обновляет таймер. Если бы они складывались, огнемёт с пятью звёздами
сжигал бы босса за пару секунд.

Статусы видно без подписей: горящий зомби краснеет и обзаводится язычками
пламени, а замороженный **вмерзает в льдину** — `drawFlames` и `drawIceBlock`
в [sprites.js](../js/render/sprites.js). То же самое рисуется и на боссе:
`drawBoss` принимает те же флаги, а размеры эффектов считаются от радиуса,
поэтому на крупной фигуре они не разъезжаются.

Посмотреть на боссе живьём можно на стенде
[preview-bosses.html](../preview-bosses.html) — кнопка «Стихия» переключает
огонь и лёд, а прогресс заморозки там идёт по кругу, чтобы были видны трещины.

Льдина устроена так:

- **неправильный многоугольник**, а не круг. Первая версия рисовала ровно одну
  окружность вокруг зомби, и это выглядело дёшево — не возвращайтесь к этому;
- грани, блик и сосульки по нижнему краю;
- при `freezeProgress > 0.65` лёд идёт **трещинами**, при `> 0.85` осыпается
  осколками — видно, что заморозка вот-вот спадёт.

Лёд намеренно полупрозрачный (0.28), а сам зомби тонируется в голубой лишь
слегка (0.3). Сильная тонировка плюс плотный лёд — и зомби сливается с глыбой,
становится непонятно, кого именно заморозили.

Снаряды вешают эффект через крючок `onHit(enemy, world)` — он объявлен в базовом
`Projectile` и вызывается из [collisions.js](../js/systems/collisions.js).
Обычные снаряды его просто не переопределяют.

## Оружие без снарядов: меч и лазер

Два оружия не создают `Projectile` вовсе.

`LightSaber.fire()` перебирает врагов и бьёт всех в секторе перед героем.

**Лазер** устроен так же, только сектор заменён отрезком, а разовый взмах —
таймером прожига. Почему именно так, а не иначе:

- **частые пробивающие снаряды** отдали бы урон на откуп частоте кадров: одна
  и та же капля била бы одного зомби каждый кадр полёта;
- **своя сущность-луч** потребовала бы второй ветки в `collisions.js` (там
  только круг с кругом) ради одного оружия. Если однажды понадобится луч
  босса — то есть луч, живущий отдельно от стреляющего, — правильный ответ
  будет именно этот.

Луч рисует сам класс, переопределяя `draw()` целиком, как вертушка. Даром
получает мировые координаты и тряску: `Player.draw` вызывается внутри
`applyShake`.

Две вещи, которые легко сломать:

- **лазер не зовёт `setActiveWeapon`.** Ствола в руке у него нет, и перехват
  руки на 0.35 секунды показал бы ребёнку пустые ладони вместо его пистолета.
  Вертушка молчит по той же причине;
- **ветки в `WEAPON_IN_HAND` у него нет намеренно** — вторая пустая рука после
  вертушки. Это не забытая ветка.

## Световой меч

Единственное оружие, которое не создаёт `Projectile`: `LightSaber.fire()`
перебирает врагов и бьёт всех, кто попал в сектор перед героем (проверка по
расстоянию `reach` и разнице углов `arc`). След взмаха рисует
`particles.addSlash()`.

Задел на будущее: если понадобится ещё оружие ближнего боя — берите меч за
образец, а не вертушку: вертушка работает по таймеру контакта, а меч бьёт
разово по команде.

## Стартовое оружие

Ребёнок выбирает его сам на экране `screens/weapons.js` при первом запуске.
Выбор хранится в `save.weapon` и попадает в раунд через
`Game.getUpgrades().startWeapon` → `Round.createStartingWeapon()`.
Если выбора нет (старое сохранение), берётся `CONFIG.startingWeapon`.

Короткие детские описания оружия («Крутится вокруг тебя», «Редко, зато бабах!»)
лежат в `WEAPON_HINTS` в том же файле — при добавлении нового оружия допишите
строку и туда, иначе на карточке будет пусто.

Важно: любое стартовое оружие должно быть проходимым, см.
[balance.md](balance.md).

## Оружие в руке

У героя видно то оружие, из которого он **только что выстрелил** — так ребёнок
связывает картинку в руке с тем, что летит по экрану.

Механика собрана в базовом `Weapon`, поэтому все виды получают её даром:

- `aimAngle` — угол на ближайшего врага, обновляется **каждый кадр**, даже пока
  идёт перезарядка. Если обновлять только при выстреле, ствол дёргается рывками;
- `recoil` — таймер отдачи, ставится в `fire()`;
- `draw()` — рисует ствол, но только если это оружие сейчас активно.

Само рисование — `drawWeaponInHand()` в [sprites.js](../js/render/sprites.js):
общий код разворачивает контекст по углу прицела и отодвигает ствол назад при
отдаче, а `switch` по id рисует конкретное оружие «от руки вперёд» вдоль оси X.
Добавляя оружие, допишите туда ветку — иначе в руке будет пусто.

Две тонкости, которые пришлось учесть:

- **Ствол не должен вставать вверх ногами.** При стрельбе влево контекст
  отражается по вертикали (`ctx.scale(1, -1)`), а не разворачивается целиком.
- **Размер берём с запасом.** В бою герой мелкий (радиус ~20 px), и оружие,
  которое выглядит правильным на превью, в игре не разглядеть.

Какое оружие в руке, решает `Player.setActiveWeapon()`. Там же живёт защита от
мельтешения: чужой ствол не перехватывает руку, пока не истёк короткий таймер
удержания (`player.weaponHoldTime`). Исключение — **редкое оружие**: ракета
стреляет раз в три секунды, и без приоритета её бы вечно перебивал частый
водяной пистолет, так что в руке она не появлялась бы вовсе.

Вертушка — единственная без ствола в руке: её лопасти и так крутятся вокруг
героя, она переопределяет `draw()` целиком.

## Эволюция на пятой звезде

Оружие с полем `evolution` на пятой звезде **заменяется новым экземпляром**, а
не получает флаг: флаг превратил бы восемь классов в шестнадцать веток
`if (evolved)`, а «другое ощущение» требует другого кода стрельбы.

| Оружие | → | Что меняется |
|---|---|---|
| 💧 Водяной пистолет | 🌊 Водомёт | струя пробивает четверых насквозь (`PiercingBullet`) |
| 🍅 Помидорометалка | 🍝 Помидорная пушка | три помидора веером (поле `count`) |
| ⚔️ Световой меч | 🗡 Двойной меч | круговой взмах на 360° (только числа) |

Правило, которое держит фичу от разрастания: **сначала попробуй выразить
эволюцию числом в конфиге, новый класс заводи, только когда меняется
механика.** Три превращения проходят все три пути разом — новый снаряд, новое
поле в родительском классе, чистая арифметика.

`evolution` — **id обычного оружия**, а не вложенный блок: эволюция обязана
быть полноценным оружием (класс, ствол в руке, эмодзи в HUD, озвучка на
паузе). Флаг `evolved: true` прячет её из `ALL_WEAPON_IDS`, то есть из выбора
стартового оружия и из карточек «новое оружие».

**Карточка пятой звезды и есть карточка эволюции** — с новым именем и новой
картинкой ещё до того, как её взяли, и она **всегда попадает в набор**, а не
разыгрывается наравне с прочим: это цель всей прокачки внутри раунда, и
прятать её в случайности значит обесценить фичу.

Ловушка, которую закрывает `createStartingWeapon`: «Сильный старт» из магазина
может вывести оружие сразу на пятую звезду, а карточка апгрейда для
максимального не выпадает — без явной проверки превращения не случилось бы
никогда.

Добавляя эволюцию, не забудьте ветку в `WEAPON_IN_HAND` — иначе рука пустая.

## Ограничения

Одновременно герой носит не больше пяти оружий (`MAX_WEAPONS` в
`systems/levelup.js`). Когда слотов не осталось, карточки предлагают только
апгрейды; когда и апгрейдов не осталось — сердечко, чтобы экран выбора никогда
не оказался пустым.
