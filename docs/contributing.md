# Как дорабатывать проект

## Соглашения

- **Один модуль — одна ответственность.** Класс сущности не знает про экраны,
  экран не знает про зомби, оружие общается с миром только через API `Round`.
- **Никаких магических чисел в коде.** Всё, что можно покрутить, живёт в
  `js/config.js`. Появилась новая константа — заведите поле в конфиге.
- **Комментарии объясняют «почему», а не «что».** Строка `this.x += vx * dt`
  в пояснении не нуждается; а вот почему интервал делится на корень из
  сложности — нуждается.
- **Русские названия в интерфейсе, английские в коде.** Имена классов, методов и
  полей на английском, текст для ребёнка — на русском.
- Никаких зависимостей и сборки. Открыл файл — увидел код, который выполняется.

## Рецепты

### Добавить оружие

Подробно в [weapons.md](weapons.md): характеристики в `CONFIG.weapons`, класс в
`weapons/weapons.js`, регистрация в `WEAPON_CLASSES`. В карточки прокачки оно
попадёт само.

### Добавить фон

1. Новый элемент в `CONFIG.themes`:
   ```js
   { name: 'Пещера', ground: '#4a4a55', accent: '#3a3a45', deco: 'crystals' },
   ```
2. Ветка `case 'crystals'` в `Background.drawDecoration()`
   (`js/render/background.js`) и функция рисования рядом с `drawFlower`.

Темы переключаются по кругу каждые `CONFIG.roundsPerTheme` раундов.

### Добавить вид зомби

Обычно новый класс не нужен — достаточно записи в `CONFIG.zombieTypes`:

```js
{
  id: 'ninja', name: 'Ниндзя',
  hp: 0.5, speed: 2.0, radius: 0.75, weight: 2, fromRound: 8,
  look: { skin: '#9fd6c0', clothes: '#2b2b3d', body: 'thin', hair: 'spiky' },
},
```

Поля `hp`/`speed`/`radius` — множители к базовым значениям раунда. Помните
правило из [balance.md](balance.md): быстрый обязан быть хрупким.

Если нужна новая деталь внешности (шляпа, борода, крылья), добавьте её в
`drawZombie()` в `js/render/sprites.js` рядом с `drawHelmet` и заведите
соответствующее поле в `look`.

**Зомби-животное** рисуется иначе — `look.shape: 'beast'` уводит отрисовку в
`drawBeastZombie()`. Новому зверю нужна ветка в `drawBeastHead()` и
`drawBeastTail()`, остальное (тело, лапы, глаза, клык) общее.

**Особое поведение** задаётся полем `behavior` и веткой в
`Zombie.updateBehavior()`. Если поведение касается появления, а не движения
(как стая собак), его место — в спавнере, а не в зомби.

Врага с другим поведением (стреляет, прыгает) уже стоит сделать классом в
`js/entities/`, унаследованным от `Zombie` — как сделан `Boss`.

### Добавить персонажа

Запись в `CONFIG.characters`:

```js
{
  id: 'pirate', name: 'Пират', about: 'Больше монет',
  perk: { speedBonus: 20 },
  ability: 'shockwave',   // id из CONFIG.abilities
  look: {
    skin: '#f0c088', hair: '#3b2a1c', hairStyle: 'cap',
    shirt: '#c94f4f', pants: '#2f3550', cape: null, chest: 'none',
    hat: { color: '#1c1c1c', letter: 'P' },
  },
},
```

Он сам появится на экране выбора — захардкоженных знаний о конкретных героях
в коде нет ни одного.

Поддерживаемые значения `look`:

| поле | значения |
|---|---|
| `hairStyle` | `bowl`, `cap`, `antenna`, `ears`, `quills`, `pikaears` |
| `chest` | `star`, `bolt`, `text` (+ `chestText`), `spider`, `none` |
| `hat` | `{ color, letter }` или отсутствует |
| `cape` | цвет или `null` |
| `mask` | цвет — закрывает лицо целиком и рисует линзы вместо глаз |
| `cheeks` | цвет — румяные щёки (Пикачу) |

Для зомби и боссов есть ещё два: **`stone: true`** — тело собирается неровными
глыбами вместо скруглённых форм (голем), и **`cracks`** — цвет трещин.
| `build` | `normal` (по умолчанию) или `buff` — телосложение (Халк) |
| `brows` | цвет — злые брови домиком вниз |
| `mouth` | `snarl` — открытая пасть с клыками вместо улыбки |
| `muzzle` | цвет — светлая морда на нижней половине лица (Соник) |
| `gloves` | цвет — перчатки вместо цвета кожи на руках |
| `shoes` | цвет — широкие носки поверх низа ног |

**`build` меняет только картинку, не хитбокс.** Столкновения и притяжение
медалек считаются по `player.radius`, а он от телосложения не зависит: широкий
Халк получает удары ровно так же, как узкий Котик. Это осознанно — иначе выбор
героя по внешности тихо менял бы сложность.

`build` тянет за собой не только торс, но и ноги с руками: при широком теле и
прежних ногах качок выходит на спичках. Проверено глазами.

**Про «злое» лицо — три грабли подряд, все видны только на картинке:**

- **брови**: внутренний конец (у переносицы) обязан быть НИЖЕ наружного —
  «\ /». Наоборот, «/ \», получается расстроенное лицо. Первая версия была
  именно такой, и Халк вышел грустным;
- **рот**: просто опущенная дуга тоже читается как «расстроен». Злость даёт
  ОТКРЫТАЯ пасть, и углы её должны быть ниже середины. Ровная белая полоса
  зубов при этом превращает оскал в улыбку — нужны треугольные клыки;
- **пресс**: только заливкой. Штрихи, расходящиеся от центральной вертикали,
  читаются рыбьим скелетом, а сплошные поперечины — решёткой. Обе версии были
  сделаны и обе забракованы глазами.

Три пары полей **не сочетаются**, и это видно только на картинке:
`muzzle` вместе со светлым `shirt` (голова и торс соприкасаются, и два светлых
пятна сливаются в одно — лицо пропадает); `mask` с чем угодно лицевым (маска
рисуется вместо всего); `brows` без контрастного цвета относительно кожи.

Неизвестное значение не падает: причёски и эмблемы просто не рисуются. А вот
`look: null` уронит — фолбэк `DEFAULT_LOOK` срабатывает только при полном
отсутствии ключа.

**Маска трогает глаза, и это опасное место.** Зрачки лежат в константе
`HERO_EYES`, и по ней же бьёт лазер (`heroEyePoints` → `weapons.js`). Линзы
рисуются ПО этим координатам и лишь крупнее; сдвинете глаза — луч уедет с лица.

Перки читаются в `Game.getUpgrades()` — новое поле перка нужно там же и
учесть. Все ключи идут через `|| 0`, поэтому отрицательный перк работает сам
(так у Халка `speedBonus: -35`).

Перки держите слабыми: выбор героя не должен делить персонажей на сильных и
слабых. Способность можно взять чужую, но интереснее своя — см. рецепт ниже.

**Своё оружие.** Поле `fixedWeapon: 'id'` выдаёт герою оружие всегда и
отключает ему выбор (так у Человека-паука). Само оружие пометьте
`signature: true`, иначе оно будет предлагаться и всем остальным. Подробности —
в [weapons.md](weapons.md) и [screens.md](screens.md).

### Добавить суперспособность

1. Запись в `CONFIG.abilities` — `name`, `emoji`, `about` детским языком,
   `color` (не жёлтый: он занят шкалой опыта) и параметры;
2. класс в `js/systems/ability.js`, наследник `Ability`. Хуков три, и обычно
   нужен один: `activate(world, owner)` — разовый эффект в момент нажатия,
   `tick(dt, world, owner)` — каждый кадр, пока идёт `duration`,
   `drawWorld(ctx)` — если эффект живёт в мире, а не на герое. Длящийся эффект
   **на самом герое** (быстрее, чаще стреляет) ставится таймером на нём, как
   `turbo()`, а не хранится внутри способности; `tick` нужен только тогда, когда
   способность каждый кадр делает что-то с миром — как портал, который тянет
   зомби;
3. регистрация в `ABILITY_CLASSES`;
4. `ability: 'ваш-id'` у героя в `CONFIG.characters`.

HUD, звёздочки готовности, звук и озвучка карточки подхватятся сами. А вот
анимацию работающей способности нужно дописать самому — веткой в
`drawAbilityEffect()` ([sprites.js](../js/render/sprites.js)); без неё
способность будет действовать молча. Мгновенным способностям вроде волны ветка
не нужна. А если эффект стоит в мире, а не вокруг героя (портал), рисуйте его
своим `drawWorld(ctx)`: `drawAbilityEffect` умеет только координаты героя.

Проверьте способность и в момент выхода босса: `Round.useAbility()` там
намеренно не срабатывает.

Урон наносите через `world.damageEnemy()`, а не трогая `enemy.hp` руками: это
единственная точка, где начисляются заряд, добыча, наклейка и счётчик убитых.
Способность, бьющая мимо неё, тихо ломает половину прогресса.

### Посмотреть рисовку, не заходя в бой

В корне лежат четыре стенда — обычные HTML-страницы, которые импортируют
настоящие `config.js` и `sprites.js`. Правите спрайт — стенд меняется вместе с
игрой, расхождения быть не может:

| Стенд | Что показывает |
|---|---|
| [preview-heroes.html](../preview-heroes.html) | восемь героев: походка, мигание после удара, звёздочки заряженной способности и анимация работающей; кнопка «Развернуть» проверяет зеркальную отрисовку |
| [preview-zombies.html](../preview-zombies.html) | семнадцать видов зомби в трёх состояниях: обычный, горящий, замороженный |
| [preview-bosses.html](../preview-bosses.html) | пятеро боссов: походка, ярость и стихийные статусы |
| [preview-locations.html](../preview-locations.html) | четыре темы фона |

Открывать их надо через тот же локальный сервер, что и игру: ES-модули по
`file://` не грузятся.

### Добавить питомца

1. Запись в `CONFIG.pets` (скорость, урон, кулдаун, внешность);
2. класс в `js/entities/pet.js` — наследник `Pet`, переопределяется `attack()`
   и `drawBody()`;
3. регистрация в `PET_CLASSES`;
4. товар в `CONFIG.shop` с полем `pet: 'ваш-id'` и ценой из одного элемента.

Больше ничего: `getUpgrades()` соберёт питомцев по полю `pet`, а магазин
покажет товар как обычный. Не забудьте `dog: 0`-подобный ключ в `DEFAULT_SAVE.shop`.

### Добавить эволюцию оружия

1. `evolution: 'новый-id'` у родителя в `CONFIG.weapons`;
2. запись самой эволюции там же с `evolved: true` (массивы характеристик
   длиной 1 — норма);
3. класс, только **если меняется механика**. Если хватает чисел —
   зарегистрируйте эволюцию на класс родителя в `WEAPON_CLASSES`
   (родительские классы принимают id параметром);
4. ветка в `WEAPON_IN_HAND` — иначе рука будет пустой.

### Добавить особый раунд

1. Запись в `CONFIG.specialRounds` и id в `order`;
2. класс в `js/systems/modifier.js` — переопределяются нужные крючки
   (`tuneSpawner`, `update`, `onLoot`, `drawWorld`);
3. регистрация в `MODIFIER_CLASSES`.

Помните правила: `onLoot` только добавляет добычу, `tuneSpawner` работает один
раз.

### Добавить наклейку в альбом

Ничего не нужно: альбом строится по `CONFIG.zombieTypes` и `CONFIG.bossTypes`.
Единственное — у нового вида должно быть поле `about`, короткая детская фраза
для карточки и для голоса.

### Поменять сложность

См. [balance.md](balance.md) — там таблица «хочу → что менять» и автотест,
которым стоит проверить результат. Правя базовые числа, помните: они общие для
всех трёх уровней, а `CONFIG.difficulties` — только множители поверх них.

### Добавить уровень сложности

Одна запись в `CONFIG.difficulties` — экран выбора соберётся сам, как и в
случае героев и оружия. Правило одно: **все поля обязательны**, дефолтов у
них нет, иначе уровень молча унаследует чужое поведение.

Здоровье зомби задаётся парой `hpRoundOffset` / `hpEveryRounds`, а не
множителем — почему именно так, написано в [balance.md](balance.md).

### Переименовать героя

Поле `name` в `CONFIG.characters` — больше нигде имя не дублируется.

## Чеклист перед тем, как отдать игру ребёнку

Запустите `start.command` и пройдите весь путь:

1. **Меню**: при первом запуске одна кнопка «НОВАЯ ИГРА», она ведёт по цепочке
   **выбор героя → выбор оружия → бой**. Когда прогресс есть, появляется
   «ПРОДОЛЖИТЬ» (сразу в бой) и «Новая игра» (спрашивает подтверждение
   и стирает всё).
2. **Раунд**: герой бегает стрелками, оружие стреляет само, зомби лопаются
   конфетти, медальки и доллары притягиваются. К раунду 6 в толпе видны все
   семнадцать видов зомби: собаки прибегают стаей, котик виляет, крот ныряет
   под землю, шарик летит по воздуху, ролик проезжает мимо, тыква лопается и
   задевает соседей, снеговик разваливается надвое, а с девятого раунда ниндзя
   исчезает в дымке и появляется с другой стороны.
3. **Сложность**: «Новая игра» ведёт сложность → герой → оружие. На «Сложно»
   у героя на одно сердечко меньше, зомби заметно быстрее, а долларов за раунд
   вдвое больше. В меню рядом с 💵 и 🏁 видно эмодзи уровня.
4. **Способность**: шкала под опытом копится, примерно на 20-м зомби звенит и
   вокруг героя вьются звёздочки; пробел применяет её и обнуляет шкалу. Пробел до
   этого момента не делает ничего и заряд не тратит.
5. **Прокачка**: при новом уровне появляются три карточки; работают и мышь,
   и стрелки с Enter.
6. **Озвучка**: кнопка 🔈 на карточках героев, оружия, прокачки, товаров
   магазина и на паузе произносит название голосом; клик по динамику не
   выбирает карточку. Переключение стрелками читает название само.
7. **Босс** выходит через две минуты, объявляется голосом, у него полоска
   здоровья, после победы — салют. В раундах **1–12** боссы должны быть
   разными. Костяной (раунд 6) рассыпается и встаёт ровно один раз, а наклейку
   даёт только после второй смерти.
   Появляется он **в кадре**, со своим эффектом (падение / вихрь / рывок /
   льдина / огненный столб); зомби на это время замирают, экран коротко
   трясётся, а HUD при этом стоит на месте.
8. **Стихии**: огнемёт поджигает (зомби с язычками пламени), ледяная пушка
   морозит (зомби синеет и ползёт), меч рубит дугой сразу нескольких.
9. **Прицеливание**: оружие молчит, пока зомби не вошёл в кадр.
10. **Магазин**: покупка списывает доллары, четыре товара и кнопка «ГОТОВО»
   помещаются на экран целиком.
11. **Поражение**: экран «Почти получилось!», без слова GAME OVER.
12. **Пауза** по Esc и обратно; на ней виден список собранного оружия.
13. **Звук**: кнопка 🔊 выключает и звуки, и голос.
14. **Сохранение**: перезагрузить страницу — доллары и покупки на месте,
    «Продолжить» возвращает в тот же раунд. «Новая игра» спрашивает
    подтверждение; отмена оставляет прогресс, подтверждение обнуляет всё,
    кроме настройки звука.
15. **Геймпад**: пройти путь целиком только с него — меню, выбор сложности,
    героя и оружия крестовиной и A, бой стиком, способность на A, пауза на
    Start, карточка прокачки и магазин.
16. **Планшет**: открыть игру на планшете (адрес сервера в локальной сети),
    пройти раунд пальцем — герой идёт туда, где палец, и продолжает идти, если
    палец **не двигать**; кнопка способности загорается, работает пауза ⏸.
    На десктопе контролов быть не должно.
17. **Вдвоём**: «Новая игра» → «Вдвоём» → двое выбирают героев, оружие и
    карточки прокачки **одновременно, каждый в своей колонке**; первый не может
    выбрать за второго; переход дальше — только когда готовы оба. В бою у
    каждого свои сердечки и способность, кольца у ног разного цвета; падение
    одного не заканчивает раунд.
17б. **Одному** те же три экрана обязаны выглядеть ровно как раньше — одна
    панель без заголовков «ИГРОК N». Это регрессия, которую легко не заметить.
17г. **Человек-паук**: одному — экран оружия не показывается вовсе, в руках
    паутина. Вдвоём с другим героем — колонка Паука заблокирована и уже
    «ГОТОВ», вторая листается. Паутина не появляется ни в выборе у других
    героев, ни карточкой «новое оружие».
17в. **Телефон**: узкое окно (375×812) — в HUD только сердечки, таймер, тонкая
    полоса опыта и слоты оружия справа; кнопка способности слева и ничего не
    перекрывает. На планшете и десктопе HUD прежний.
18. **Питомец**: купить собачку в магазине — бежит следом, не наступает на
    героя, кусает зомби и отличима от зомби-собаки.
19. **Эволюция**: докачать оружие до пятой звезды — карточка «ВЫРОСЛО!», салют,
    голос, в руке новый ствол, в HUD звезда вместо точек. Эволюция есть у всех
    одиннадцати, и проверять её надо **выдачей**: класс-родитель, зашивающий
    свой id в `super()`, молча отдаёт характеристики родителя, ничего не роняя.
    После эволюции исходное оружие **не должно** снова выпасть первого уровня.
20. **Особый раунд**: раунд 4 — дождь медалек, 8 — ночь (всё видно!), 12 —
    толпа. Голос объявляет, в HUD эмодзи.
21. **Альбом**: открытые наклейки цветные, закрытые — силуэт с ❓, обе
    озвучиваются; «Новая игра» альбом не стирает.
22. **Консоль браузера чиста** — ни одной ошибки.

Пункты 2–7 можно проверить быстро, не проходя раунд руками: см. автотест в
[balance.md](balance.md). После автотестов сбросьте прогресс — кнопкой «Новая
игра» в меню или через `localStorage.clear()` в консоли, — иначе ребёнок
начнёт с чужим прогрессом.

## Известные особенности

- ES-модули не работают по `file://` — игру нужно открывать через локальный
  сервер (`start.command` делает это сам).
- Голосовая озвучка требует системного русского голоса. На macOS это Milena,
  она есть по умолчанию. Если голоса нет, игра просто молчит и работает дальше.
- Браузер кеширует `css/style.css` жёстко. Если правки стилей не видны, откройте
  страницу с Cmd+Shift+R.
- `window.game` в `main.js` — намеренный отладочный хук, а не забытая отладка.
